# Bench record — write path: neode vs raw Cypher (NTS-654)

**Run date:** 2026-11-11 · **Bench:** `bench/write-bolt.bench.ts` (`vitest bench --project unit bench/write-bolt.bench.ts`)
**Environment:** Apple M4 Max, macOS 26.7.2, Node v24.19.0, neo4j:5-community testcontainer (Docker Desktop), neode 1.0.0-next.1, neo4j-driver 6.x, local Bolt (localhost)

Each bench writes N deterministic rows (`BenchWriteUser { id, name, email, counter }`, `id` unique-constrained via `installSchema()`) exactly once, from an empty graph. Every strategy receives the identical per-row payload. Wall-clock is the vitest bench `mean` of the single N-row run; statement counts come from `QUERY_EXECUTED` events (neode paths) and explicit run counters (raw driver paths), captured by the bench into `write-bolt-latest.json`.

## Wall-clock (ms) for the whole N-row write

| Strategy | 300 rows | 3,000 rows | 30,000 rows |
|---|---:|---:|---:|
| neode `create()` per row | 1,155 | 3,686 | 27,672 |
| neode `createMany()` (UNWIND, 1000-row chunks) | 89 | 115 | 790 |
| neode `merge()` per row | 740 | 3,699 | 28,452 |
| neode `mergeMany()` (MERGE UNWIND, 1000-row chunks) | 94 | 113 | 893 |
| raw driver `CREATE` per row | 341 | 2,102 | 21,561 |
| raw driver — one `UNWIND` batch | 30 | 39 | 284 |

## Statements per write

| Strategy | 300 | 3,000 | 30,000 |
|---|---:|---:|---:|
| neode `create()` per row | 300 | 3,000 | 30,000 |
| neode `createMany()` | 1 | 3 | 30 |
| neode `merge()` per row | 300 | 3,000 | 30,000 |

## Readings

- **Batching dominates, not the OGM pipeline.** `createMany()`/`mergeMany()` land within ~3x of the raw single-statement `UNWIND` ceiling (the gap is 1 statement per 1000-row chunk + row preparation vs 1 statement total) and are 8–35x faster than per-row writes. The per-row OGM overhead over the raw per-row baseline is roughly 1.3–3.4x per row — round-trips per statement dominate wall-clock, so statements-per-write is the number to optimise first.
- **Per-row cost is stable once warm.** The 300-row run pays warm-up (first statements after container start: ~1.1 ms/row raw, ~3.9 ms/row neode); from 3,000 to 30,000 rows the per-row cost holds at ~0.7 ms (raw) and ~0.9–1.2 ms (neode) against a growing graph with a uniqueness constraint — no super-linear decay at these sizes.
- **Merge vs create costs the same** per row (~213 ms vs ~238 ms at 30 rows; ~28.5 s vs ~27.7 s at 30k) — `merge()`'s MERGE-on-match-key statement is not meaningfully more expensive than the CREATE path.
