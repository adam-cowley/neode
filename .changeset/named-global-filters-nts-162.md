Named global filters with pattern-comprehension relations (NTS-162): `@Filter({ name, where, default })` declares named read filters on a model, `setFilterParams(name, value)` parameterises them, and every standard read (find / get / all / paginate / findManyAndCount / lazy / chunk / search / knn / projections / eager loads / repository reads) composes them from one central place in the query services. `{ withoutFilters: ['name'] }` (or the reserved `'*'`) disables filters per query — each name independent, with the built-in @SoftDelete filter addressable as `softDelete` and `includeDeleted` still honoured. Filtered relations render the target model's filters as a WHERE inside the relation's pattern comprehension (or the `with` load spec's COLLECT subquery) — a filtered-out target simply doesn't match, the relation reads as absent (`[]`) and the parent row survives; never OPTIONAL MATCH. Soft delete composes as a label predicate (labels-as-state, NTS-128). Documented and tested bypasses: raw Cypher (readCypher/writeCypher/cypher), hand-built Builders, and bulk writes (deleteAll, and the write paths' internal re-hydration, which use the `'*'` bypass).
