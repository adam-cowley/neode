`Neode#parallel()` — fan an array (or named map) of operations across concurrent sessions (NTS-631). Mode `read` (default) runs one READ autocommit session per operation — N independent reads in one wall-clock batch; mode `write` runs concurrent autocommit writes with no cross-operation atomicity (failures surface per operation in a `ParallelError` aligned with the input); mode `atomic` opens one WRITE transaction per operation, runs the bodies in parallel and commits them sequentially only if every body succeeded — any failure rolls back every open transaction (a commit-phase failure remains the documented residual risk, surfaced per handle). Operations are callbacks receiving a `ParallelScope` (a session- or transaction-bound Runner with the facade's build-and-run sugar), not promises. `TransactionalService#parallel()` delegates the autocommit modes through the parent connection and rejects atomic mode — a scoped transaction cannot fan out. Caveats documented: parallel writes touching the same nodes serialize on locks (keep operation sets node-disjoint), and the embedded Relate engine queues transactions one-at-a-time per connection — correct there, but atomic mode with more than one operation deadlocks on Relate (use the autocommit modes or one sequential transaction instead).
