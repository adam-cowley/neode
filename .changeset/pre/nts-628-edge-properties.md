Edge properties on declared relationships (NTS-628). The map API's `properties` key on a relationship definition is now honoured as the edge-property schema: every write accepting edge properties — `relate()`, nested creates (via `create()`'s `relationshipProperties` carrier, NTS-627) and the new `updateEdgeProperties()` — validates against it, throwing naming the relationship key for unknown properties or wrong types. `relate()` with properties now upserts them on the MERGE (`ON CREATE SET` / `ON MATCH SET`; `forceCreate` keeps the plain SET). New `neode.updateEdgeProperties(entity, key, target, props)` (also on `TransactionalService` and the `INeode` port): matches both nodes by identity, MERGEs the edge — never duplicating it — and SETs the properties; idempotent per re-run. Edge properties are readable today through relationship-entity eager loads (the edge projects with its own `.*`), the `GraphRelationship` value relate()/updateEdgeProperties return, and raw reads; carrying edge properties of node-target relationships through the eager projection is a documented follow-up (it changes the hydrated shape). Expression-valued edge properties: follow-up, will reuse the NTS-629 scalar-expression helper — literals only for now.
