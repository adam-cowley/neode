1.0 security review of every place user-controlled input can reach generated Cypher (NTS-675). Values were already parameter-only; this pass closes the remaining identifier holes and documents the trust boundary. `Builder#where` (and `whereNull` / `whereIn` / `whereContains` / `whereStartsWith` / `whereEndsWith` / `whereBetween`) now backtick-escape their property/reference argument like pattern keys already did (plain `n.name`-style references render unchanged), the `where` operator validates against the known comparison / membership / string / regex set (with `whereRaw()` as the escape hatch), `set()` / `onCreateSet()` / `onMatchSet()` validate their operator (`=`, `+=`, `-=`; `setExpr()` is the escape hatch), pattern aliases and path variables must be plain identifiers (`match` / `optionalMatch` / `create` / `merge` / `to` / `relationship` / `asPath` / `whereId`), and a SET key carrying backticks is now escaped instead of passing through verbatim. A hostile string in any of these positions now fails closed (quoted into an inert identifier, or a descriptive `NeodeError`) instead of reaching the statement. The Querying page of the generated agent docs and the API reference gained a trust-boundary section; `RelationshipService.delete` also now matches relationships through `whereId` instead of a hand-composed `elementId()` expression.
