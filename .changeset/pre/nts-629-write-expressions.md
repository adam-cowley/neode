Expression properties on create()/merge() (NTS-629): a property-map value may be a `RawExpression` (NTS-460) and the raw Cypher renders verbatim into the write statement — `create(Model, { id: 'a', prevHash: new RawExpression('…') })` — evaluated once by the database, so value-computing writes (hash-chain heads, derived keys, `SET copy = properties(src)` clone copies) stop paying a read-then-write round trip. Rendering rule: every expression property renders as a trailing `SET this.prop = <expression>` clause after the CREATE / MERGE pattern, in the write path's canonical map order (schema-declared property order) — a later expression may reference an earlier property of the same write via the node alias, and parameters the expression references must already be bound in the statement (a literal property's own parameter, e.g. `$this_id`, or a service-bound one). Inside a CREATE / MERGE pattern the node variable is not yet bound, so set values never ride the inline pattern (match-key expressions on mergeOn()/merge() keep the NTS-460 inline rendering — they match, not set). Expressions skip write-time property validation (the value is not known to JavaScript); validation still applies to every literal property, and the stored value is checked against the property's type on the next read. SET-side expressions: verified on neo4j-driver backends; on the embedded Relate engine, avoid pattern syntax inside expressions until verified.
