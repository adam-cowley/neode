Stored derived properties (NTS-569): `@Derived({ from, compute | cypher })` (decorator) / `derived: { … }` (map API) computes a property's value on the write path from the `from` source properties and stores it like a hand-set value — the write-time counterpart of `@Computed`. A write touching any source recomputes the property on every write path (create / save incl. dirty-tracked saves / mergeOn / update patches / bulk), an explicitly provided value always wins, and the recomputed keys join the tracked write set. Two producers: `compute` runs in TypeScript against the entity's property record (output flows through `in` transforms and validation); `cypher` is a raw expression the database evaluates inside the write statement with `this` bound to the written node after the sources are set — rendered as its own `SET` clause, because the embedded Relate engine drops the trailing items of a SET clause that mixes parameter and expression forms. Exactly one producer is required and every `from` source must be a declared property; violations throw on the model's first write. `Builder` now renders parameterised and raw (expression) SET items as run-length-grouped separate SET clauses (valid Cypher, applied in order; ON CREATE/ON MATCH SET keep their single-clause shape per NTS-491).
