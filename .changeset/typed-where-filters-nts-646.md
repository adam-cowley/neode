Typed where filters keyed to the model's declared properties (NTS-646): the `where` bags of get / getFirst / first / all / paginate / findManyAndCount / chunk / lazy / withinDistance (facade + transactional mirrors) and the Repository read bags (findBy / findAll / where / count / countBy / deleteAll) take `WhereFilter<C>` — equality values and operator objects (`{ age: { gte: 18 } }`) are checked against the model's declared property keys, relationship keys take nested filter bags, and a mistyped key or operator is a compile error instead of a silently-unfiltered query. The operator set maps 1:1 onto the Builder's methods: eq, neq, gt, gte, lt, lte, in, contains, startsWith, endsWith, null — `between` composes as `{ gte, lte }`, and the raw-Cypher escape hatch (`Builder.where`) is untouched. Runtime Cypher for existing queries is unchanged: the duplicated equality loops (facade get / withinDistance / deleteAll, Repository matchAll, PaginateService) collapsed into one shared helper, with the projection path rendering its nested traversal through the same operator helpers. The runtime tier fails loud everywhere the compile check cannot see: an unknown bag key throws (with a did-you-mean), a nested relationship bag on a non-projection read throws (it would silently filter nothing — on deleteAll that is an unfiltered wipe), an empty operator object throws, and a plain-map equality value on an object-valued property needs the `{ eq: … }` wrapper (there is no object property type, so this is the escape for any-typed fields). Keyset pagination (paginate with after/before, lazy, chunk) renders the operator tier too — its hand-written statement emits the same `Where` / `WhereNull` clauses through a shared condition renderer instead of rejecting operator objects.
